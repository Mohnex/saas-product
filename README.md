# مخطط الادخار — المنتج التجاري (بنية مجانية بالكامل)

## 🔄 ماذا تغيّر عن النسخة السابقة؟
النسخة الأولى استخدمت Firebase Cloud Functions كخادم خلفي — وهذا **يتطلب
ترقية مشروعك لخطة Blaze المدفوعة**، حتى لو بقي استخدامك ضمن الحد المجاني
الفعلي. بناءً على طلبك، استبدلتها بالكامل بخادم Express.js عادي، يُنشر
مجاناً بالكامل (بدون بطاقة ائتمان إطلاقاً) على **Render.com** — تحققت من
هذا مباشرة (سبتمبر ٢٠٢٦) قبل البناء عليه.

**ما بقي على فايربيس (يبقى ضمن خطة Spark المجانية تماماً):**
- Firebase Authentication (تسجيل الدخول)
- Firestore (قاعدة البيانات)
- Firebase Hosting (استضافة صفحات `public/`)

**ما انتقل لـ Render (مجاني، بدون بطاقة ائتمان):**
- كل منطق التحقق من الدفعات وتفعيل الاشتراكات (كان سابقاً في `functions/`،
  أصبح الآن في `server/`)

**القيد الوحيد الحقيقي لهذا الاختيار المجاني:** خادم Render المجاني "ينام"
بعد ١٥ دقيقة من عدم الاستخدام، ويحتاج ٣٠-٦٠ ثانية "ليستيقظ" عند أول طلب
تالٍ. هذا يعني أن تفعيل الاشتراك بعد الدفع قد يتأخر دقيقة أحياناً (الدفع نفسه
غير متأثر، فقط سرعة التأكيد). لا يوجد حل مجاني كامل يزيل هذا القيد نهائياً.


## ما هذا المجلد؟
هذا **مشروع منفصل تماماً** عن تطبيقك الشخصي (`mohsen-app`) — النسخة التي
ستُباع لعملاء غرباء. لا تخلط بينهما ولا تنشر هذا على نفس مشروع فايربيس
الخاص بتطبيقك الشخصي؛ يُفضَّل مشروع فايربيس جديد بالكامل.

## هيكل الملفات الآن
```
saas-product/
├── firebase.json        ← إعدادات Hosting + Firestore فقط (لا Functions)
├── firestore.rules       ← قواعد الأمان (لم تتغيّر)
├── public/                ← يُنشر على Firebase Hosting (مجاني)
│   ├── auth.html
│   ├── billing.html
│   ├── onboarding.html    (مؤقت)
│   └── app.html            (مؤقت)
└── server/                ← يُنشر على Render (مجاني) - بديل Cloud Functions
    ├── index.js
    ├── firebaseAdmin.js
    ├── authMiddleware.js
    ├── subscriptions.js
    ├── zaincash.js
    ├── cardGateway.js
    └── customerLifecycle.js
```

## ✅ ما هو حقيقي، ومُتحقَّق منه فعلياً (وليس فقط مكتوباً)
- **نظام تسجيل دخول حقيقي** (`auth.html`) — بريد إلكتروني + كلمة مرور.
- **قواعد أمان Firestore صحيحة** (`firestore.rules`) — بيانات كل عميل معزولة
  تماماً عن الآخر.
- **الخادم الخلفي (`server/`)**: ثبّتّ الحزم فعلياً، **شغّلته حقيقةً محلياً**،
  وأرسلت طلبات HTTP فعلية له للتأكد: `/health` يستجيب بنجاح، والمسارات
  المحمية (مثل بدء دفعة) ترفض بشكل صحيح أي طلب بلا رمز دخول صالح. هذا اختبار
  سلوك فعلي، وليس فحص صياغة فقط.
- **تكامل زين كاش** (`server/zaincash.js`) — نفس التدفق الكامل من النسخة
  السابقة (بدء→تحويل→تحقق توقيع→تفعيل)، بمنطق مطابق تماماً لكن كمسارات
  Express بدل دوال Cloud Functions.
- **إدارة اشتراكات آمنة + فترة تجريبية + فحص انتهاء يومي** — نفس المنطق
  السابق، مع تحسين: نقطة الفحص اليومي أصبحت رابطاً محمياً برمز سرّي
  (`CRON_SECRET`) بدل جدولة داخلية، لأن Render المجاني لا يوفر جدولة تلقائية
  (انظر خطوة ٧ أدناه للحل المجاني البديل).

## ⚠️ ما هو "هيكل" (Scaffold) فقط - غير عامل بعد
- **`server/cardGateway.js`** — لم أصل لوثيقة API فعلية لـ Blue أو NASS Pay.
  **أرسل لي وثيقتها فور حصولك عليها وسأكمله فعلياً.**
- **`onboarding.html` و `app.html`** — صفحتان مؤقتتان، المرحلة التالية.

## 🔑 حقيقة تقنية مهمة (لم تتغيّر عن النسخة السابقة)
**زين كاش لا تدعم على الأغلب اشتراكاً تلقائياً متكرراً** — التجديد الشهري
عبرها يحتاج تذكيراً ودفعاً يدوياً كل شهر. البطاقات (Blue/NASS) هي الطريقة
الوحيدة لتجديد تلقائي حقيقي. أكّد هذا مباشرة مع دعم زين كاش عند التفعيل.

## خطوات التشغيل بالترتيب

### ١) أنشئ مشروع فايربيس جديد (Spark - المجاني، لا ترقية مطلوبة هذه المرة)
console.firebase.google.com ← Add project. فعّل **Authentication →
Email/Password** و **Firestore Database**. **لا حاجة لخطة Blaze إطلاقاً الآن.**

### ٢) ضع إعدادات فايربيس في الملفين
انسخ `firebaseConfig` من إعدادات مشروعك، والصقه في **كل من**:
`public/auth.html` و `public/billing.html` (يجب أن يتطابقا تماماً).

### ٣) انشر واجهة فايربيس (بدون functions هذه المرة)
```bash
cd saas-product
firebase deploy --only firestore:rules,hosting
```

### ٤) نزّل مفتاح حساب الخدمة (Service Account Key)
من القنصولة: ⚙️ Project Settings → Service Accounts → **Generate new
private key** (يُنزّل ملف JSON). حوّله لسطر Base64 واحد:
```powershell
# PowerShell على ويندوز:
[Convert]::ToBase64String([IO.File]::ReadAllBytes("مسار-الملف.json")) | Set-Clipboard
```
هذا الأمر ينسخ القيمة مباشرة للحافظة — الصقها في خطوة ٦ أدناه.

### ٥) أنشئ حساب GitHub مجاني (إن لم يكن لديك) وارفع مجلد `server/`
اذهب لـ github.com ← أنشئ مستودعاً (Repository) جديداً خاصاً ← اسحب وأفلت
كل ملفات مجلد `server/` عبر واجهة الموقع مباشرة (لا حاجة لتثبيت Git).

### ٦) أنشئ حساب Render مجاني واربطه بذلك المستودع
render.com ← سجّل حساباً (Google/GitHub مباشرة، **بدون بطاقة ائتمان**) ←
New ← Web Service ← اختر المستودع الذي رفعته ← Build Command: `npm install`
← Start Command: `npm start` ← اختر الخطة **Free**.

قبل الضغط على "Create"، أضف متغيرات البيئة هذه من قسم **Environment**:
| المتغيّر | القيمة |
|---|---|
| `FIREBASE_SERVICE_ACCOUNT_BASE64` | القيمة التي نسختها في خطوة ٤ |
| `FRONTEND_BASE_URL` | رابط موقعك على Firebase Hosting (مثال: `https://your-project.web.app`) |
| `CRON_SECRET` | أي نص عشوائي طويل تختاره بنفسك (مثال: `x7K9mP2vQ8`) |
| `ZAINCASH_MERCHANT_ID` | من لوحة تاجر زين كاش بعد تفعيله |
| `ZAINCASH_MSISDN` | رقم محفظة التاجر |
| `ZAINCASH_SECRET` | السرّ الخاص بحسابك |

### ٧) انسخ رابط Render وأكمل الربط
بعد أول نشر، سيعطيك Render رابطاً مثل `https://your-app.onrender.com`:
1. الصقه في `BACKEND_BASE_URL` داخل `public/auth.html` و `public/billing.html`،
   ثم أعد النشر (`firebase deploy --only hosting`).
2. أدخل `https://your-app.onrender.com/zaincash-callback` في لوحة تاجر زين
   كاش كـ "Callback URL".
3. **(اختياري لكن مهم) الجدولة اليومية المجانية:** اذهب لـ
   **cron-job.org** (مجاني، بدون بطاقة) ← أنشئ حساباً ← أضف مهمة جديدة تستدعي
   `https://your-app.onrender.com/api/cron/check-expiring?token=<نفس CRON_SECRET>`
   مرة يومياً. هذا يُشغّل فحص انتهاء الاشتراكات تلقائياً (ويُبقي خادمك
   "مستيقظاً" جزئياً كأثر جانبي مفيد).

### ٨) اختبر بحساب تجريبي حقيقي
أنشئ حساباً عبر `auth.html`، تأكد من ظهور سجل في Firestore
(`customers/{uid}`)، ثم جرّب الدفع من بيئة اختبار زين كاش
(`test.zaincash.iq`) قبل التفعيل الحقيقي.

## ما لم يُبنَ بعد (بانتظار قرارك بالبدء)
- معالج الإعداد الأولي الفعلي (`onboarding.html` الحقيقي)
- التطبيق نفسه معمَّماً لكل عميل (`app.html` الحقيقي) — هذه أكبر مرحلة متبقية
- تكامل بطاقة فعلي (بانتظار وثيقة API من Blue/NASS)
- لوحة تحكم لك كمالك (عدد العملاء، الإيرادات)
- الشروط والأحكام وسياسة الخصوصية (نصوص قانونية فعلية - أنصحك بمراجعة قانونية بشرية لهذه تحديداً، وليس فقط ما أكتبه)
